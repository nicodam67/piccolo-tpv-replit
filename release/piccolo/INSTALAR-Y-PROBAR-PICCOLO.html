Instalar y probar Piccolo

Versión: 0.9.0-rc.2 · Canal: pruebas / preproducción

VERSIÓN DE PRUEBAS — NO USAR PARA FACTURACIÓN FISCAL REAL.
No configure AEAT producción. Use únicamente datos y cobros marcados como prueba.

1. Qué descargar

  1. Descargue el ZIP cuyo nombre empieza por Piccolo-TPV-0.9.0-rc.2-Hardware-Test-.
  2. Haga clic derecho → Extraer todo.
  3. Abra BUILD-MANIFEST.json y compruebe que muestra la versión 0.9.0-rc.2 y el mismo commit indicado en el informe de entrega.

2. Elegir dónde estará el servidor

Elija solo una opción como servidor principal durante cada prueba:
  • Opción A — Windows: la más sencilla para comenzar inmediatamente.
  • Opción B — TerraMaster: use Docker Manager/TOS.
Los demás PC, tablets, KDS y teléfonos se conectan a ese servidor por la red local.

3. Instalar servidor Windows

  1. Abra 02-Windows-Servidor.
  2. Clic derecho sobre Piccolo-Server-Windows-…exe → Ejecutar como administrador.
  3. Elija Instalación nueva.
  4. Si solicita PostgreSQL 16, permita instalarlo y anote la contraseña en un lugar seguro.
  5. Acepte el nombre piccolo.local y el puerto interno 8080.
  6. Cuando termine, abra https://piccolo.local/setup.
  7. Windows puede indicar “Editor desconocido”: esta RC no está firmada con Authenticode.

Correcto cuando el navegador muestra el asistente Piccolo y http://127.0.0.1:8080/api/healthz responde ok.

4. Instalar servidor TerraMaster

  1. Abra 03-TerraMaster y copie el archivo Piccolo-TPV-…-TOS-linux-amd64-….tar.gz al NAS.
  2. Entre por SSH con una cuenta administradora.
  3. Extraiga el archivo en una carpeta nueva de Piccolo; no use ningún paquete del repositorio QR.
  4. Ejecute sudo ./linux/install-tos.sh y elija Docker.
  5. Guarde la contraseña generada y compruebe los contenedores postgres, piccolo y caddy.
  6. Abra desde otro dispositivo https://piccolo.local/setup.

5. Instalar el TPV en Windows

  1. Abra 01-Windows-TPV y ejecute Piccolo-TPV-Windows-…exe.
  2. Escriba la dirección del servidor, normalmente https://piccolo.local.
  3. Abra el acceso directo Piccolo TPV.
  4. Complete el primer administrador, empleados, salas, mesas y productos.
  5. Compruebe login, apertura de caja, mesa, comanda y pantalla de cobro.

6. Conectar tablets y teléfonos

  1. Conecte el dispositivo a la Wi-Fi del restaurante.
  2. Compruebe que sigue en la misma Wi-Fi aunque se desconecte Internet.
  3. Abra Chrome y escriba https://piccolo.local/.
  4. Si aparece aviso de certificado local, instale la CA de Caddy siguiendo al técnico.
  5. Chrome → menú de tres puntos → Añadir a pantalla de inicio.
  6. Pruebe login, camarero, salas, mesas, productos, modificadores, notas, enviar comanda y modificar según permisos.

No se necesita APK: Piccolo funciona como web/PWA en LAN.

7. Abrir KDS

En cada pantalla KDS abra una dirección distinta:

DepartamentoDirección
Cocinahttps://piccolo.local/kds/cocina
Pizzahttps://piccolo.local/kds/pizza
Ensaladashttps://piccolo.local/kds/ensalada
Barhttps://piccolo.local/kds/barra
Pasehttps://piccolo.local/kds/pase

Use modo pantalla completa o quiosco. En Administración → KDS configure las estaciones.

8. Configurar impresoras ESC/POS

  1. Asigne una IP fija a cada impresora y confirme el puerto TCP 9100.
  2. Piccolo → Administración → Impresoras → Añadir.
  3. Indique departamento, IP, puerto, ancho 58/80 mm y copias.
  4. Pulse Imprimir prueba.
  5. Compruebe: €, ñ, acentos, ¿?, ¡!, alimentación y corte.
  6. Configure producto/categoría → impresora y envíe una comanda de prueba.

La RC usa ESC/POS TCP real cuando está empaquetada. USB directo sin adaptador de red no está soportado en esta RC.

9. Reenvío y reimpresión

  1. Administración → Cola de impresión.
  2. Seleccione trabajo → reintentar o reimprimir.
  3. Para reimpresión escriba el motivo obligatorio.
  4. Compruebe usuario, fecha/hora, motivo y encabezado REIMPRESIÓN.
  5. En KDS use “Reenviar” sobre una tarea.

La reimpresión sólo crea un trabajo de impresión; no crea otra factura ni otro RF.

10. Fichaje

  1. Abra https://piccolo.local/fichaje/tablet.
  2. Empareje la tablet desde Administración → Fichaje → Dispositivos.
  3. Pruebe PIN, entrada, descanso, fin de descanso y salida.
  4. Compruebe el resultado en Administración → Fichaje → Registros.

No se necesita Anviz.

11. Prueba sin Internet

  1. Con todo funcionando, desconecte únicamente el cable WAN/Internet del router.
  2. No apague router, switch, servidor ni Wi-Fi local.
  3. Abra mesa, añada producto y envíe comanda.
  4. Confirme KDS e impresión.
  5. Cobre una operación claramente marcada como PRUEBA.
  6. Compruebe ticket y RF con estado pendiente_envio.
  7. Reinicie una tablet y confirme que puede reconectar al servidor LAN.
  8. Restaure Internet y confirme que no se configuró AEAT producción.

12. Pruebas de fallos

Acción controladaResultado esperado
Apagar tabletServidor/KDS continúan; al encender recupera estado.
Reiniciar TPV WindowsNo duplica pagos/comandas; vuelve a login.
Desconectar impresoraTrabajo queda en reintento/error; KDS continúa.
Reconectar impresoraReintentar desde cola; auditoría conserva el fallo.
Desconectar KDSComanda persiste; KDS la recupera al volver.
Perder/recuperar Wi-FiAviso offline; no afirmar éxito sin respuesta; refresca al volver.
Reiniciar servidorDispositivos muestran desconexión; datos confirmados reaparecen.
Perder InternetLAN sigue; RF permanece pendiente.

13. Guardar un diagnóstico

  1. Administración → Diagnóstico.
  2. Pulse Descargar informe de soporte.
  3. Guarde el ZIP y anote qué estaba haciendo, dispositivo, hora y resultado esperado.
  4. Si el servidor no abre, ejecute el recolector de 05-Diagnostico.

El ZIP excluye contraseñas, tokens, certificados, variables secretas y copias de base de datos.

14. Fin de la sesión

  1. Exporte el registro de resultados.
  2. Cierre la caja de prueba.
  3. Realice una copia de seguridad verificada.
  4. No pase a producción fiscal aunque todos los pasos sean correctos.
